JWT 用户认证与 WebSocket 认证聊天室整合汇报

本次将原本独立的 HTTP JWT 认证能力和 WebSocket 心跳通信能力串联成一个新的 IM playground： 用户先通过手机号验证码登录获得 JWT，随后使用 JWT 完成聊天室 WebSocket 连接认证，认证成功后才允许心跳和聊天消息。

整体流程

正式 IM 产品中，WebSocket 连接不能只代表“网络已连通”，还必须绑定用户身份。 因此本次采用“连接后第一条消息认证”的方式：WebSocket 先建立，再发送 JWT，服务端验证通过后把连接绑定到 user_id。

sequenceDiagram participant RN as "React Native Playground" participant Auth as "HTTP Auth API" participant WS as "WebSocket /chat_room" participant Store as "JWT / User Store" RN->>Auth: "POST /auth/sms 手机号" Auth-->>RN: "返回 6 位验证码" RN->>Auth: "POST /auth/login 手机号 + 验证码" Auth->>Store: "校验验证码 / 登录即注册" Auth-->>RN: "返回 JWT token + user_id" RN->>Auth: "GET /user/profile Authorization: Bearer token" Auth-->>RN: "返回用户资料" RN->>WS: "连接 ws://host:port/chat_room" WS-->>RN: "auth_required" RN->>WS: "{\"type\":\"auth\",\"token\":\"JWT\"}" WS->>Store: "校验 JWT 并解析 user_id" alt "Token 有效" WS-->>RN: "auth_success" RN->>WS: "{\"type\":\"ping\"}" WS-->>RN: "pong" RN->>WS: "{\"type\":\"chat\",\"content\":\"hello\"}" WS-->>RN: "chat message" else "Token 无效" WS-->>RN: "auth_failed" WS--xRN: "关闭连接" end

后端实现

端点

  • GET /chat_room：认证聊天室 WebSocket。
  • GET /chat_room/status：普通 HTTP 状态说明，方便快速确认端点存在。

认证规则

  • 连接建立后服务端先发送 auth_required。
  • 客户端第一条业务消息必须是 {"type":"auth","token":"..."}。
  • 服务端复用 JWT 解析逻辑，拿到 user_id 后查内存用户。
  • 认证失败返回 auth_failed 并关闭连接。
客户端认证消息：
{
  "type": "auth",
  "token": "JWT_TOKEN"
}

认证后的聊天消息：
{
  "type": "chat",
  "content": "你好"
}

结论

当前 playground 已经形成一个更接近正式 IM 产品的最小闭环：HTTP 登录获取身份凭证，WebSocket 连接通过 JWT 绑定用户身份，认证后再进行心跳和聊天通信。 这为后续接入真实会话、群聊、离线消息、消息 ACK、重连补偿和 Token 刷新打好了边界清晰的基础。
