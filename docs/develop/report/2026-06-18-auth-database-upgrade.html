2026-06-18 · Auth Database Upgrade

认证系统数据库升级汇报

本次升级把 playground 认证系统从“内存/简单用户模型”推进到 MySQL 持久化账号模型，并补齐密码设置、密码修改、登录后密码引导标识和前端测试覆盖。

升级目标

  • 用户数据从进程内存升级为可持久化的 MySQL 数据模型。
  • 用 accounts、user_profiles、auth_credentials、sms_codes 表拆开身份、资料、凭据和验证码职责。
  • 登录响应增加 account_id、has_password、should_set_password，供客户端判断是否需要引导设置密码。
  • 保留现有短信登录、密码登录、JWT profile 和认证聊天室能力。

数据库模型

accounts

账号主体，保存稳定身份、账号编号和状态。它是认证系统里的“人是谁”。

user_profiles

展示资料，和账号保持 1:1，保存昵称、头像、签名等前端可展示信息。

auth_credentials

登录凭据，和账号保持 1:N。当前使用 credential_type = phone，手机号作为 identifier，密码哈希保存在 secret_hash。

sms_codes

短信验证码，记录验证码、过期时间和消费时间。正式环境可继续演进为 Redis TTL。

后端改造

文件 变化
server/auth.go 扩展登录响应，新增密码设置/修改请求结构、Store 接口方法、JWT 用户解析复用和密码校验逻辑。
server/auth_mysql_store.go 切换到四表模型，短信验证码写入 sms_codes，密码使用 bcrypt 哈希保存到 auth_credentials.secret_hash。
server/router.go 新增 /auth/profile、/auth/password/setup、/auth/password，保留 /user/profile 兼容旧客户端。
server/migrations 新增 goose 迁移文件，覆盖账号、资料、凭据、短信验证码和旧验证码表升级。
scripts/database 新增创建、迁移、状态、重置、删除和启动前迁移脚本，脚本会检测并安装 goose。

接口变化

认证接口保持简单，但语义更接近正式 IM 产品：HTTP 登录拿 JWT，后续 HTTP profile 和 WebSocket 聊天室都用 JWT 证明身份。

POST /auth/sms POST /auth/login GET /auth/profile POST /auth/password/setup PUT /auth/password 

{
  "token": "jwt-token",
  "user_id": "u_000001",
  "account_id": "u_000001",
  "has_password": false,
  "should_set_password": true
}

前端改造

  • AuthSession 增加 accountId、hasPassword、shouldSetPassword。
  • AuthApi 切换 profile 到 /auth/profile，新增设置密码和修改密码请求。
  • 登录成功后，如果 shouldSetPassword = true，用户认证 playground 会展示设置密码引导。
  • 个人信息页展示“已设置登录密码 / 未设置登录密码”。
  • 认证聊天室测试数据同步升级到新登录响应，确保跨模块仍能复用认证层。

兼容与边界

  • 后端仍保留 /user/profile，兼容旧客户端；新客户端使用 /auth/profile。
  • JSON 仍返回 user_id，同时增加 account_id，方便前端逐步迁移命名。
  • 当前密码凭据复用 credential_type = phone 行的 secret_hash 字段，后续可扩展邮箱、微信、设备等凭据类型。
  • JWT 密钥仍是 playground 配置，生产环境需要改为环境变量或密钥管理系统。
  • 验证码落 MySQL 便于学习观察，生产环境更适合 Redis TTL 和频率限制。
