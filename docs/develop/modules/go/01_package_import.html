Go 代码拆分：package 与 import

这篇文档介绍当前 server 项目最适合的 Go 拆分方式：先在同一个 package main 下拆文件， 等领域稳定后，再考虑拆目录和独立 package。

package 同目录下相同 package 的多个 .go 文件属于同一个包。
import 只有使用其他包时才需要 import，同包文件之间不需要。
可见性 Go 通过首字母大小写决定符号是否能被其他包使用。

1. 当前项目里最常用的拆分方式

Go 的代码组织有一个很重要的特点：

同一个目录下的多个 .go 文件，只要 package 名相同，就属于同一个包。

比如当前后端项目：

server/
├── main.go
├── auth.go
├── ws.go
├── chat_room.go
└── main_test.go

这些文件开头都是：

package main

所以它们虽然写在不同文件里，但在 Go 看来都属于同一个包。

main.go 里可以直接使用 auth.go 里的 handleLogin
main.go 里可以直接使用 ws.go 里的 handleWebSocket
main.go 里可以直接使用 chat_room.go 里的 handleChatRoomWebSocket

不需要写：

import "./auth"

也不需要写：

auth.handleLogin

因为它们本来就在同一个 package main 里。

2. 同包拆文件：最适合当前 playground 阶段

当前项目最适合先使用“同包拆文件”：

server/
├── main.go              启动入口
├── router.go            路由注册
├── config.go            配置读取
├── network.go           本机 IP 和访问地址打印
├── version.go           /v 接口
├── conversation.go      /conversation 接口
├── auth.go              JWT 认证
├── ws.go                WebSocket 心跳练习
└── chat_room.go         认证聊天室

这些文件都继续使用：

package main

好处是调用简单：

func setupRouter() *gin.Engine {
    router := gin.New()

    router.GET("/v", handleVersion)
    router.GET("/conversation", handleConversations)
    router.POST("/auth/login", handleLogin)
    router.GET("/chat_room", handleChatRoomWebSocket)

    return router
}

即使 handleVersion、handleLogin、handleChatRoomWebSocket 分别在不同文件里，也可以直接调用。

这就是 Go 里最基础、最轻量的拆分手段：拆文件，不拆 package。

3. import 是什么时候用的

import 用来引入“其他包”。比如当前 main.go 里有：

import (
    "log"
    "net"
    "net/http"
    "os"
    "sort"

    "github.com/gin-gonic/gin"
)

标准库

  • log
  • net
  • net/http
  • os
  • sort

第三方库

  • github.com/gin-gonic/gin

导入后，使用方式通常是：

log.Printf("server started")
net.JoinHostPort(host, port)
http.StatusOK
gin.New()

也就是：

包名.符号名

4. 自己创建子包时怎么 import

如果未来项目继续变大，可以把代码拆成多个目录，每个目录就是一个包。

server/
├── go.mod
├── main.go
└── internal/
    ├── config/
    │   └── config.go
    └── chatroom/
        └── hub.go

go.mod 里当前模块名是：

module learningai/server

那么如果要在 main.go 里引入自己的子包，路径应该从模块名开始：

import (
    "learningai/server/internal/config"
    "learningai/server/internal/chatroom"
)

使用时：

cfg := config.Load()
hub := chatroom.NewHub()

同包拆文件

直接用函数名。

setupRouter()
handleLogin()

跨包拆目录

import 后用 包名.函数名。

config.Load()
chatroom.NewHub()

5. 大小写决定是否能被其他包使用

Go 里没有 public、private 关键字，而是靠首字母大小写控制可见性。

小写开头：只在当前包内可见。

func setupRouter() *gin.Engine {
    // ...
}

大写开头：可以被其他包 import 后使用。

func NewHub() *Hub {
    // ...
}

如果当前只是同一个 package main 下拆文件，可以继续使用小写函数名：

handleLogin
handleUserProfile
handleChatRoomWebSocket

如果未来把聊天室拆成独立包，例如 internal/chatroom，那么需要对外暴露的构造函数通常要改成大写：

chatroom.NewHub()

6. 当前项目推荐的拆分策略

现在后端还处在 playground 阶段，不建议一上来就拆很多 package。

更稳妥的顺序是：

第一步：同一个 package main 下拆文件
第二步：等某个领域稳定后，再考虑拆目录和 package

比如现在可以先这样拆：

main.go
├── 只保留 main 启动流程

router.go
├── setupRouter

config.go
├── ServerConfig
├── loadServerConfig
├── getEnv

network.go
├── printAccessURLs
├── localIPv4s
├── ipFromAddr

conversation.go
├── ConversationResponse
├── fakeConversations
├── handleConversations

version.go
├── appName
├── appVersion
├── VersionResponse
├── handleVersion

这些文件仍然全部写：

package main

这样 main.go 会变薄，但测试和调用方式都不需要大改。

7. 一个简单判断标准

只是为了让文件更清楚：
    拆文件，保留同一个 package。

已经形成独立领域，并且希望被多个地方复用：
    拆目录，创建新 package。

需要对外暴露能力：
    使用大写开头的符号。

只在包内部使用：
    使用小写开头的符号。
对当前项目来说，下一步最推荐的是：先拆文件，不急着拆 package。
